# Правила для ИИ-инженера: Server-setings

1. СНАЧАЛА прочитайте `README.md`, `docs/00-НАЧНИ-ЗДЕСЬ.md`, `snapshots/2026-10-19/test-ubuntu.json`, `docs/05-API-И-MCP.md` и `SECURITY.md`.
2. Различайте **эталон текущего сервера**, **желаемую конфигурацию**, **проверенную функцию**, **предположение**. Не называйте новую установку проверенной без реального прогона на чистой Ubuntu.
3. Реальная тестовая Ubuntu: `admins-MS-7D22`, LAN `192.168.1.115`, Tailscale `100.75.149.26`; школьный Windows с адресами `172.23.*` и VPS `161.104.46.160` — другие узлы. Не путайте их.
4. Используйте GitHub-first. Один исполнитель пишет ветку; другой проводит независимое review; обязательны точный SHA и тесты. Нельзя сливать недоказанную инфраструктуру, нарушая доступность.
5. Нельзя автоматически перезапускать Docker, UFW, DNS, Netplan, NetworkManager, Tailscale, SSH и менять порты старых систем без отдельной задачи, записи отката и проверки текущего доступа. Нельзя форматировать/чистить тома.
6. Скрипты работают в режиме плана без `--apply`; любые необратимые изменения требуют явного подтверждения и свежей диагностики. Работающий OpenResty нельзя заменить независимым Caddy.
7. API-ключи, SSH-пароли, приватные сертификаты, возрастные ключи age, .env, дампы PostgreSQL и данные MinIO **не публикуйте в GitHub, включая private**. Не вставляйте их в CI, PR или логи. Секреты хранятся на машине владельца с правами 0600, резервные копии — в `age` с внешним recipient.
8. **1Panel**: управление сайтами/сертификатами в интерфейсе/API. Публичный OpenResty на 80/443. Отдельный локальный Caddy на 192.168.1.115:4610, а контейнер ASA Lab на 127.0.0.1:4610. Вмешиваться напрямую в 1Panel DB и генерируемые vhost-файлы нельзя.
9. Действующий Compose-проект — `asa-lab-dev` даже при production-профиле. Не переименовывать и не делать `docker compose down -v`. Данные ASA Lab восстанавливаются исключительно через согласованную процедуру собственного репозитория.
10. MCP предоставляется по принципу минимальных прав: `readonly` по умолчанию, локальный loopback, токен. Нельзя публиковать HTTP MCP наружу; повышение до readwrite — отдельное решение владельца. В 1Panel API-ключ при этом сам по себе административный.
11. При невозможности связи с устройством записать `UNKNOWN`/`STOP`, а не использовать вчерашний IP/пароль и не делать слепую правку.
12. После каждой работы обязательно обновлять снимок `snapshots/`, журнал изменений в PR и матрицу доказательств из `docs/08-ПРОВЕРКИ-И-ОГРАНИЧЕНИЯ.md`.

13. Новый школьный узел `serv` — **другой хост**, не `admins-MS-7D22`: Ubuntu 26.04.1, изолированный профиль `school-tailnet`. Разрешённые сети и порт 1Panel должны подтверждаться живым чтением; панель на школьный LAN не публиковать. Любые `--apply` и UFW — после физического пути восстановления и проверки Tailscale SSH. Runbook: `docs/24-SCHOOL-UBUNTU2604.md`. Наличие Tailscale SSH само по себе не даёт `sudo` без пароля.

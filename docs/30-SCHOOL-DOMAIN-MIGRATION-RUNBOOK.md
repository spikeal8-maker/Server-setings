# Школьная VM100: безопасная смена домена ASA Lab

**Фактическое состояние на 01.11.2026.** Текущий публичный адрес — `https://x.asa-lab.ru`, исходящий FRP-профиль `asa-frpc.service` на `asa-school-01` направляет этот домен на `127.0.0.1:80`. OpenResty установлен и управляется **1Panel VM100**; сайт `asa-lab-x` проксирует запросы на `http://127.0.0.1:4610`. Публичный HTTPS/TLS-сертификат выдаёт внешний Leticia / Traefik, а **не** панель VM100. Текущий `x.asa-lab.ru/health/ready` подтверждён HTTP 200/TLS valid/schema 286.

## Важно: новый адрес или перенос действующего основного домена

- **Дополнительный домен:** сначала создавайте новый HTTPS-вход **параллельно** действующему `x.asa-lab.ru`. До приёмки не удаляйте ни старый домен, ни FRP-маршрут, ни сертификат.
- **Перенос `asa-lab.ru`:** это уже работающий основной сайт другого production-контура. Такой переход требует отдельного согласованного cutover с проверенным полным бэкапом, rollback-окном и возможностью немедленно вернуть старый адрес на предыдущий продакшн. Нельзя просто заменить A-запись DNS или перенаправить `asa-lab.ru` на школу.
- Изменение домена **не означает** миграцию базы или её восстановление. PostgreSQL/MinIO и volumes не пересоздавать; `docker compose down -v` запрещён.

## Порядок переключения с контролем каждого слоя

1. **До изменений:** зафиксировать работающую `https://x.asa-lab.ru/health/ready`, выпуск/срок действующего Let's Encrypt на Leticia, исходные vhost Traefik, 1Panel website и закрытую копию `/etc/asa-frpc/frpc.toml` на VM100. Проверить резервное копирование ASA Lab (не только Docker Healthy) и выбрать путь отката.
2. **1Panel VM100 → Сайты:** добавить новое доменное имя как управляемый сайт/домен или второй отдельный reverse-proxy vhost с тем же upstream `http://127.0.0.1:4610`. Не создавать новый экземпляр ASA Lab или пустую PostgreSQL. Проверить локальный HTTP по `Host` нового имени.
3. **VM100 FRP:** в существующем `/etc/asa-frpc/frpc.toml` сохранить `serverAddr=161.104.46.160`, `serverPort=7000` и путь на OpenResty `localIP=127.0.0.1, localPort=80`, добавить новый `customDomains` к HTTP-proxy. Выполнить проверку конфигурации и перезапустить **только** `asa-frpc.service` с автоматическим возвратом файла и рестартом при ошибке. Не менять Proxmox bridge, firewall, локальный порт 1Panel 19192 и настройки базы.
4. **Внешний VPS Leticia/Traefik:** завести для нового имени независимый host rule и настоящий сертификат Let's Encrypt, проверить ACME challenge и автоматическое продление. Не копировать приватные TLS-ключи в VM100 ради заполнения раздела «Сертификаты». Действующий `x.asa-lab.ru` продолжает обслуживаться прежним сертификатом/правилом.
5. **DNS Selectel:** назначить новый A/AAAA/CNAME в соответствии с подтверждённым ingress **Leticia**, а не Proxmox/VM100/private Tailnet-IP. До включения уменьшить TTL для планируемой записи; проверить DNS-ответы из независимых сетей и TLS/SNI снаружи. Для домена, уже обслуживающего другой production, сначала подготовить проверенный rollback DNS и не менять запись до завершённой приёмки нового адреса.
6. **ASA Lab / конфигурация безопасности:** обновить **только реально существующие** публичные URL и разрешённые origins (CSRF/CORS, cookies, OAuth redirect, Web/Scratch/API endpoints) с учётом нового адреса. Не угадывать имена переменных: сначала прочитать текущую конфигурацию и release contract в репозитории `asa-lab`. Старый origin сохранить до отработки rollback. Не отключать CSRF и проверки cookie ради обхода 403.
7. **Приёмка нового домена:** из внешней сети выполнить TLS/hostname/SNI, `/health/ready` 200, API, login преподавателя/ученика, открытие курса, Scratch/Electronics save/reopen, загрузку файлов и корректность WebSocket. Убедиться, что **старый домен** также работает. Проверить метрики и логи на Leticia/FRP/OpenResty/ASA, исключить зацикливание redirect.
8. **Только после успешной приёмки:** переключить основной адрес/redirect. Сохранить старый HTTPS-маршрут на переходный срок и контролировать TLS renewal. Для `asa-lab.ru` перенести production-трафик только после отдельной согласованной приёмки и проверки текущих живых данных.
9. **Откат:** если новый домен не проходит TLS/вход/сохранение, вернуть DNS/Traefik на прежний host, FRP из защищённой копии, предыдущий 1Panel vhost и ASA public origins. Повторно проверить `https://x.asa-lab.ru/health/ready`, работающие аккаунты и проекты. Не использовать rollback приложения/БД только ради возврата домена.

## Команды контроля уже действующего домена

Из доверенного Windows/Linux-клиента:

```bash
curl --fail --show-error --silent https://x.asa-lab.ru/health/ready
curl --head --show-error --silent https://x.asa-lab.ru/
```

Из консоли Ubuntu VM100:

```bash
sudo systemctl is-active asa-frpc
sudo systemctl is-active server-settings-1panel-mcp
sudo asa-school-connect status
```

Эти команды не меняют конфигурацию. Изменения DNS, Traefik, FRP и конфигурации ASA Lab требуют отдельного управляемого задания: `x.asa-lab.ru` не является синонимом нынешнего production `asa-lab.ru`. Проверенную собственную конфигурацию FRP и site в 1Panel менять только с rollback.

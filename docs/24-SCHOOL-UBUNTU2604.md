# Школьный Ubuntu 26.04.1: Tailscale → Docker → 1Panel

Дата контрольного осмотра: 2026-10-22. **Это подготовительный runbook, не акт установки Docker/1Panel.**

## 1. Проверенный хост и точка управления

| Параметр | Проверено через Tailscale SSH |
| --- | --- |
| Hostname | `serv` (tailnet-имя `asa-school-serv`) |
| Ubuntu | 26.04.1 LTS, kernel 7.0.0-38-generic, amd64 |
| Учётная запись | `admins`, группа `sudo`; SSH-пароль задаётся владельцем и не публикуется в GitHub; непривилегированная SSH-сессия не имеет беспарольного sudo |
| Школьный IP | `172.23.104.191/23`, интерфейс `enp1s0`, шлюз `172.23.104.1` |
| Tailscale | `100.72.211.28`, служба `active`, Tailscale SSH включён |
| Ресурсы | 8 логических CPU, ~14 GiB RAM, ~207 GiB свободно на / |
| SSH | `ssh.socket` включён, порт 22 слушает |
| Docker / 1Panel | На дату проверки не установлены |
| UFW | `ufw status` после reboot показывал inactive; `systemctl is-active ufw` не доказывает, что правила применены |

Проверенное управление: **Ali_Robs** (Tailscale `100.98.113.107`) → `tailscale ssh admins@100.72.211.28` → `serv`, команды чтения PASS. D2-R2 видит Tailscale ping, но TCP/22 блокирует локальное сетевое окружение D2-R2; сетевые ограничения компьютера не менять.

Школьный IP/подсеть получены с реального хоста; их не переносить в домашние/VPS-профили. Доступ в LAN и включение публичных портов требуют согласования с сетевым администратором школы.

## 2. Профиль school-tailnet

`profiles/school-tailnet.json` предназначен **строго** для Ubuntu 26.04 (`resolute`):

- SSH: порт 22 разрешается из школьного `172.23.104.0/23` и по `tailscale0`; действующий SSH source включается защитным механизмом установщика.
- 1Panel: пользователь входа `admins` (с отдельным случайным паролем), порт 19192 разрешается **только через `tailscale0`**; прямой доступ к панели из школьного LAN через порт 19192 не открывается.
- Публичные 80/443: закрыты на этапе первичной установки. Ни Docker, ни панель не создают публичный сайт автоматически.
- Установка: Docker, существующий Tailscale и закреплённая 1Panel v2.3.2 с проверяемым SHA256.
- Включение UFW после установки: **меняет сетевую политику**. Проводить только при подтверждённом физическом доступе к консоли и после проверки разрешённых CIDR, firewall-правил и школьных сетевых ограничений.

Установщик проверяет `VERSION_ID=26.04` и `VERSION_CODENAME=resolute`. Прежние профили 24.04 намеренно продолжают отвергать 26.04; они не изменяются для существующего узла `admins-MS-7D22`.

**Внимание:** 1Panel v2.3.2 имеет Linux/amd64-артефакт, однако **реальная установка этого профиля на чистой Ubuntu 26.04 ещё не выполнена**. Документ не заменяет интеграционный тест, в особенности проверку работы Docker networking, netfilter и UFW после включения.

## 3. Предварительные проверки без изменений

На новом сервере как пользователь `admins`:

```bash
python3 --version
cat /etc/os-release
ip -br -4 addr
ip -4 route
tailscale ip -4
tailscale status
systemctl is-active ssh.socket tailscaled
ss -lnt
sudo ufw status verbose
sudo dpkg --audit
sudo apt-get check
```

Нужно получить доступ к исходникам репозитория (с учётом прав доступа GitHub); для отсутствующего `git` сначала отдельной штатной командой администратора установить `git`. После checkout ветки запускайте:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/serverctl.py plan --profile school-tailnet
```

**Никаких модификаций без `--apply`.** Сверить печатаемый план со школьными CIDR и штатными SSH-клиентами. Не путать хосты `admins-MS-7D22` (старая Ubuntu) и `serv` (новый школьный сервер).

## 4. Порядок установки после проверок и авторизации

Требуются разрешение владельца на изменение нового сервера, привилегии `sudo` **на самом `serv`** и физический доступ для восстановления сети. Не пересылать пароль Linux в чат и не настраивать постоянный `NOPASSWD: ALL` ради автоматизации.

```bash
sudo -v
sudo bash install.sh --profile school-tailnet --apply
```

Установщик настроит Docker, проверит наличие Tailscale и поставит 1Panel, затем применит UFW. Старые серверы не затрагиваются. Системный пользователь SSH: `admins`; пароль SSH — исключительно у владельца, не публиковать в документации или истории команд. У 1Panel отдельный пользователь `admins`, отдельный **генерируемый** пароль и секретный путь входа. Пароль и защищённый путь входа в панель будут в root-only-файле `/var/lib/server-settings/1panel-admin.env` (права 0600); **не копировать его в Git, Issue или чат**.

Проверить на `serv`:

```bash
sudo systemctl status tailscaled docker 1panel-core 1panel-agent --no-pager
sudo ufw status numbered
sudo ss -lntp
sudo python3 scripts/serverctl.py doctor
```

Для браузерного доступа с разрешённой школьной Windows-машины использовать SSH-туннель (при неизменном школьном IP):

```powershell
ssh -N -L 19192:127.0.0.1:19192 admins@172.23.104.191
```

Открыть в браузере `http://127.0.0.1:19192/` вместе с **реальным защищённым путём**, созданным установщиком и прочитанным владельцем локально. Не открывать `19192` в публичный интернет.

## 5. Этапы после 1Panel

1. Веб-вход и тест установки 1Panel, проверка сохранности доступа после перезапуска.
2. Отдельный API-ключ 1Panel и локальный `readonly` MCP из `scripts/setup-mcp.sh`; транспорт ChatGPT через авторизованный компьютер. Секреты только на сервере.
3. OpenResty и сайт ASA Lab **только после** развёртывания и проверки backend, безопасного LAN-ingress, резервирования PostgreSQL/MinIO и требований школьных VLAN.
4. Проверка нагрузки, реального входа ученика, уроков, Scratch, Electronics и сохранений.

Ни на каком этапе не удалять данные с существующего тестового сервера `admins-MS-7D22`. Публичный IP школе для SSH/Tailscale не нужен.

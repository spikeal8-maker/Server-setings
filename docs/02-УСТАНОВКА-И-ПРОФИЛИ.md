# 2. Установка с чистой Ubuntu 24.04 LTS

Цель — повторить **инфраструктурный фундамент**, а не автоматически заменять действующую базу ASA Lab. Установщик использует проверенные исходные источники, но новый хост должен пройти собственную приёмку: одна проверенная машина не доказывает, что все провайдеры/VPS автоматически заработают.

## Состав

`sudo bash install.sh --profile home-static --apply` выполняет:

1. Проверяет ОС Ubuntu 24.04, 8 ГБ свободного диска, root, отсутствие уже установленной 1Panel, свободные 80/443/19192.
2. Устанавливает системные пакеты и Docker Engine + Compose из официального APT-репозитория Docker с ключом подписи.
3. Устанавливает Tailscale из официального репозитория для Ubuntu Noble; не выполняет `tailscale up` без учётной записи пользователя.
4. Скачивает **конкретную** 1Panel `v2.3.2` из официального репозитория, сверяет SHA256 с официальным `checksums.txt` **и закреплённым `versions.lock.json`** и только затем запускает поддерживаемый non-interactive installer 1Panel на порту 19192, с русским интерфейсом.
5. Генерирует сильный административный пароль и нестандартный защищённый путь доступа. Сохраняет их только в `/var/lib/server-settings/1panel-admin.env`, режим 0600, root.
6. До включения UFW разрешает доступ по SSH из доверенных сетей; разрешает порт 19192 лишь из LAN и Tailscale; открывает 80/443 только согласно профилю. Не меняет маршруты, DNS, сетевые карты, SSH-ключи и параметры BIOS.

Для простого просмотра:

```bash
python3 scripts/serverctl.py plan --profile home-static
python3 scripts/serverctl.py plan --profile home-dynamic
python3 scripts/serverctl.py plan --profile vps
```

**Список профилей:** `home-static` — LAN плюс статический WAN IP через NAT; `home-dynamic` — LAN плюс Tailscale, без публичных 80/443; `vps` — выделенный IP, SSH/tailnet для администрирования, 80/443 для сайтов. **Не используйте примерный IP `94.29.44.211` на чужом сервере**: это адрес текущего тестового роутера, а не универсальная настройка.

Для VPS, особенно если SSH уже слушает нестандартный порт, войдите по SSH (скрипт добавит текущий SSH source в allowlist). Для запуска из консоли провайдера, без SSH, укажите доверенный адрес администратора, например `--admin-cidr 192.0.2.8/32` — документационный адрес заменять на свой реальный IP. Если ни текущей SSH-сессии, ни CIDR нет, включение firewall запрещено.

## Чего скрипт не делает без следующего шага

OpenResty устанавливается **через 1Panel**, иначе панель не сможет управлять его сайтом. После первого входа создайте ключ и выполните `scripts/panelctl.py install-openresty --apply`; создайте proxy-сайт после запуска приложения и backend. HTTPS сначала проверяется вручную и может потребовать регистрации ACME-аккаунта / DNS / HTTP-01. Это сознательный двухэтапный процесс, поскольку до первого входа на панели нет доверенного API-ключа. Скрипт не создаёт фиктивные учётные записи учеников и не восстанавливает базу без проверенной копии.

## Отказ и восстановление

Установка останавливается при занятом порту, неподдерживаемой системе, недостатке места, ошибке SHA256 или обнаружении 1Panel. Она **не удаляет существующий сервер**. Если загрузка пакета или интернет недоступны, исправьте источник доступа/заранее подготовьте проверенное зеркало; не снимайте SHA256-проверку. При частично неудавшейся установке **не стирайте** `/var/lib/server-settings` и `/opt/1panel`: сначала выясните причину и сделайте снимок текущего состояния.

Для доступа после установки выполняйте `sudo 1pctl user-info` в локальной консоли или `sudo cat /var/lib/server-settings/1panel-admin.env` только на доверенном терминале. Не отправляйте вывод в чат или issue.

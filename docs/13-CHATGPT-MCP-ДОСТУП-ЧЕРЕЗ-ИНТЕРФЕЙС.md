# 13. Как подключить ChatGPT к 1Panel через MCP (через интерфейс, по статическому IP)

**Статус 19.10.2026: НЕ ПОДКЛЮЧЕНО.** Это инструкция и программа испытаний, а не отчёт о выполненном развёртывании.

**Главная задача владельца:** дать ChatGPT и другим авторизованным агентам инструменты управления **реальной** 1Panel, без ежедневных команд в терминале. Панель остаётся единой точкой управления сайтами и контейнерами; Linux и systemd никуда не исчезают.

## Объяснение обычными словами

- **1Panel** — административный веб-интерфейс Ubuntu и Docker. Тестовый адрес внутри LAN: `192.168.1.115:19192`.
- **OpenResty** — веб-сервер Nginx + LuaJIT, который уже установлен **внутри 1Panel**. Принимает публичные запросы на HTTP 80 / HTTPS 443 и передаёт их ASA Lab. Его нельзя путать с самой панелью, с API или с MCP.
- **API 1Panel** — программные запросы от доверенных клиентов, например «получить список сайтов» или «проверить сертификаты».
- **MCP (не RCP)** — протокол инструментов для ИИ-агентов. Официальный `1Panel-dev/mcp-1panel` обращается к API 1Panel и возвращает набор разрешённых функций.
- **OAuth** — согласованный с ChatGPT способ авторизовать пользователя при подключении защищённого MCP. Обычный статический API-ключ 1Panel **не является OAuth-подключением**.

## Какая архитектура нужна

```text
ChatGPT (если доступно добавление custom MCP plugin)
     │
     │ HTTPS 94.29.44.211:443 + OAuth 2.1
     ▼
1Panel → OpenResty (существующий публичный веб-сервер)
     ├─ /             → существующая ASA Lab, НЕ МЕНЯТЬ
     ├─ /internal/...  → встроенный Scratch, НЕ МЕНЯТЬ
     └─ /mcp          → защищённый OAuth/MCP шлюз, ПОКА НЕТ
                                 │
                                 ▼
                         mcp-1panel (localhost, readonly)
                                 │
                                 ▼
                         1Panel API (127.0.0.1:19192)

Запрещён WAN-доступ к 19192, 39443, 22, 5432 и 9000.
Локальный школьный HTTPS обслуживает отдельный LAN Caddy; не удалять без замены и проверки.
```

Статический публичный IP подходит для HTTPS. **Туннель не обязателен**, дополнительный домен пока не нужен. Когда домен появится, его добавляют через 1Panel и выпускают отдельный сертификат, не меняя API 1Panel.

**Обязательное ограничение:** имеющийся `scripts/setup-mcp.sh` устанавливает только MCP с постоянным Bearer-токеном. Это НЕ полноценный OAuth 2.1 шлюз; публикация такого локального MCP в интернет как защищённого ChatGPT-плагина не считается готовой.

## Для владельца: только графические интерфейсы

### A. Сначала проверить, позволяет ли ваш ChatGPT подключать пользовательские MCP

1. Откройте ChatGPT **в браузере**.
2. В левом меню перейдите в **Plugins / Плагины**.
3. Нажмите **«+»** и найдите **«Add custom MCP server / Добавить пользовательский MCP-сервер»**.
4. Если пункта нет, **не создавайте новые API-ключи** и не пытайтесь обойти это через публичный IP. Проверьте план аккаунта и разрешения рабочей области. По документации OpenAI на дату записи полная поддержка пользовательских MCP для ChatGPT Web предоставляется Business, Enterprise и Edu при наличии нужных ролей. Для других конфигураций не обещать доступ без явной проверки.
5. Если пункт есть — сообщите исполнителю, что пользовательский MCP доступен. **Пока не создавайте подключение:** публичный MCP endpoint ещё не работает (`/mcp` отвечал 404).

### B. Что вы видите в 1Panel

1. Откройте сохранённый локальный URL 1Panel. Не используйте публичный адрес `94.29.44.211:19192` для администрирования.
2. **Сайты → Сайты**: OpenResty и один работающий публичный сайт `94.29.44.211`.
3. **Сайты → Сертификаты**: проверьте срок действия текущего IP-сертификата и признак автопродления.
4. **Настройки → API Key**: API 1Panel должен иметь авторизованный ключ для будущего MCP; не передавайте секрет в публичные Issue, PR и документацию.
5. **Контейнеры → Composes**: сюда ИИ-инженер может добавить проверенный Compose-проект MCP/OAuth после подготовки и проверки образов. **Не устанавливайте произвольный контейнер по непроверенной инструкции:** официальный mcp-1panel сейчас опубликован как Go-проект, а воспроизводимость OCI-сборки ещё должна быть подтверждена.
6. **Сайты → Конфигурация**: отдельный публичный путь `/mcp` на действующем OpenResty должен появиться только после проверки OAuth, TLS, заголовков и того, что существующая ASA Lab не пострадала.
7. **AI → MCP в самой 1Panel не означает автоматическое подключение 1Panel к облачному ChatGPT.** Эти вещи не эквивалентны.

### C. Когда серверная часть ГОТОВА: закончить подключение в ChatGPT

1. Откройте **Plugins → + → Add custom MCP server**.
2. Укажите название, например **1Panel ASA Lab (тестовый сервер)**.
3. В поле Connection вставьте **фактически проверенный** HTTPS endpoint, например `https://94.29.44.211/mcp`. **Сегодня этот URL ещё НЕ РАБОТАЕТ (404)**, поэтому не пытайтесь подключить его заранее.
4. Выберите предложенную OAuth-авторизацию и пройдите страницу входа; не вводите тестовый API-ключ 1Panel в поле OAuth Client ID/Secret. Нет опции передачи произвольного фиксированного Bearer/API-key в форме подключения.
5. Подтвердите предупреждение об опасности стороннего сервера, затем выберите **Create as a plugin**.
6. Установите созданный плагин, откройте **новый чат** и выберите его через `@`. Проверьте команды «Покажи сайты 1Panel», «Проверь сертификат IP», «Какое состояние панели?».
7. Достоверным доказательством прямого соединения считается **появление инструментов в ChatGPT и их реальные ответы без Remote Desktop Commander/D2-R2**. Старый API-отчёт с D2-R2 НЕ достаточен.

### Если ChatGPT не предлагает создание пользовательского MCP

Запишите `BLOCKED_PRODUCT_ACCESS`, ссылку на официальную документацию и видимые разрешения. Не утверждайте, что «настроено»; не создавайте публичный бесконтрольный MCP. Не навязывайте тоннель, VPN или новую подписку без решения владельца.

## Для ИИ-исполнителя: последовательность работ и проверки

1. Прочитать `AGENTS.md`, `docs/14-ЖУРНАЛ-СБОЕВ-И-ПРОВЕРОК.md`, Issue #9, #4, #8 и PR #5/#6. Сначала запрашивать **факты**, не переписывать систему с нуля.
2. Поскольку пользователь просит UI-first, управлять сайтами/сертификатами/Compose в интерфейсе 1Panel либо разрешёнными функциями 1Panel API. Не создавать независимый Caddy на 80/443; не менять Docker тома ASA Lab.
3. Закрепить конкретный исходный SHA официального `mcp-1panel`, построить и проверить OCI-образ (если используется 1Panel Compose). Создать отдельный контейнер или локальную службу; `readonly` по умолчанию.
4. Секрет API 1Panel подставлять в защищённую конфигурацию MCP; не печатать его, не встраивать в Dockerfile/image, команды с аргументами, issue, JSON ответ или GitHub Actions. Текущий тестовый ключ `asa-lab-gpt` имел `Любой IP/Бессрочно`: приемлемость для временных тестов задана владельцем, **для эталона развёртывания недопустимо**.
5. До публикации проверить локальный `tools/list`, `get_dashboard_info`, `list_websites`, `list_ssls` и запреты на неизвестные/неразрешённые инструменты. Проверить реакцию без/с плохой авторизацией.
6. Настроить **OAuth 2.1** на шлюзе/IdP (не заменять его фиксированным Bearer): protected-resource metadata, auth-server metadata, authorization code + PKCE S256, issuer ID, ресурс/audience, доступы/scopes, срок и отзыв токенов, при необходимости refresh tokens. При настройке ChatGPT используйте актуальный redirect URI, который показывает интерфейс подключения.
7. Настроить маршрут OpenResty только для защищённого HTTPS MCP на существующем 443. При проверке убедиться в корректности Host, URI path prefix, streaming и долгих запросов, защите от запросов без OAuth, отдельном журнале аудита без секретов. Не отключать origin проверки и CSRF ASA Lab.
8. С независимой WAN проверить доверенную TLS-цепочку (IP сертификат Let’s Encrypt), отсутствие открытых admin/API портов, а затем **настоящий ChatGPT plugins tool discovery**. Не считать успехом только HTTP 200/401.
9. Зафиксировать в GitHub: версию/commit/образы, конфигурацию без секретов, статус UI подключения, даты, доказательства neg/pos проверок, rollback, повторяемость после reboot. Для прав записи требуются отдельные полномочия и согласованная матрица инструментов.

**Уровни официального MCP:** `readonly` читает статус/сайты/SSL/приложения/БД; `readwrite` добавляет создание сайтов, SSL и БД; `full` добавляет установку некоторых приложений. Это **не полный функциональный эквивалент 1Panel API**. Не обещать управление обновлениями всей Ubuntu только через `mcp-1panel`.

## Типичные неисправности

| Что видите | Что это означает | Что проверить |
|---|---|---|
| API 1Panel возвращает HTTP 200, JSON `code=401` | API авторизацию отклонил | Подпись/timestamp/ключ/IP-allowlist |
| `https://94.29.44.211/mcp` → 404 | Публичный маршрут MCP отсутствует | Фактическое состояние 1Panel/прокси/Compose |
| `192.168.1.115:39443` недоступен из LAN | Локальный MCP не должен слушать LAN | Проверять только из самого сервера; `127.0.0.1` обязателен |
| OAuth discovery/token exchange fails | Нет корректных `.well-known`, issuer/PKCE/scopes либо прав ChatGPT | Сверить реальную ошибку и актуальную документацию |
| Ошибка SSL | IP-сертификат истёк или TLS цепочка недействительна | Issue #4, реальное продление, не отключать TLS verify |
| Плагин не виден в меню ChatGPT | Неподдерживаемый план/нет workspace permission/не установлен плагин | Проверить Plugins/политику/новый чат |
| MCP отвечает, но команда отсутствует | `readonly` либо инструмент не реализован | Проверить `tools/list`; использовать UI/API для остальных функций |

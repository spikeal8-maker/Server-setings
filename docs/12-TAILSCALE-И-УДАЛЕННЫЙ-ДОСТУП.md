# 12. Удалённое управление через Tailscale без публичной 1Panel

## Цель

На любом домашнем сервере или VPS должна быть возможность подключиться к SSH и 1Panel из заранее авторизованного компьютера **без проброса административных портов** на роутере. Для этого применяется Tailscale, запускаемый как отдельная служба, не зависящая от OpenResty.

Путь: `авторизованный компьютер → Tailscale → сервер:22 (SSH)` либо `сервер:19192 (1Panel)`. Никакие `443:19192`, VPN/SSH из WAN без нужды и CGNAT обходы не создаются.

## Настройка на новой Ubuntu

Базовый инсталлятор устанавливает `tailscaled`, но первая авторизация требует действий владельца. Обычный способ: `sudo tailscale up` и подтверждение ссылки в браузере. Для полностью автономного провизионирования предварительно выдаётся ограниченный ключ авторизации Tailscale; ключ хранится в файле с режимом **0600**, не в репозитории и не в аргументах с секретом. Tailscale CLI поддерживает `--auth-key=file:/...`.

Диагностика без изменений:

```bash
bash scripts/tailnet-admin.sh --ssh-port 22 --panel-port 19192
```

Применение с заранее сохранённым ключом, файл создаёт сам администратор по инструкциям Tailscale:

```bash
sudo bash scripts/tailnet-admin.sh --auth-key-file /root/tailscale-onetime.key --ssh-port 22 --panel-port 19192 --apply
```

Скрипт проверяет, авторизован ли узел. При активном Tailscale он не меняет DNS, маршруты и существующую конфигурацию. При первой авторизации использует файл ключа и отключает принятие DNS Tailscale только для нового узла, чтобы не изменять резолвер школьного/домашнего сервера. Затем добавляет разрешения UFW для SSH и 1Panel **исключительно на интерфейсе `tailscale0`**. Ключ надо отозвать/удалить по процедуре владельца после применения, если это одноразовая регистрация.

## Проверки после подключения

1. `tailscale status`, `tailscale ip -4` на сервере, `tailscale ping` с доверенного ПК.
2. **Обязательно** отдельные TCP-проверки `server:22` и `server:19192` по Tailscale IP; одного `tailscale ping` недостаточно. Проверьте tailnet ACL, UFW и клиентскую маршрутизацию. Для D2-R2 19.10 был Tailscale ping 2 мс, но TCP к обоим портам не прошёл. На ПК также запущен AdGuard VPN; его настройки без разрешения владельца не меняются.
3. С другого подключения убедитесь, что порт `19192` **не доступен из WAN**, а порт 443 сайта доступен, когда должен быть.
4. Проверить повторно после reboot Ubuntu; перед применением новых правил сохранить активную SSH-сессию и иметь доступ через консоль провайдера или физическую клавиатуру.

## Предпосылки и ограничения

Tailscale требует соединения наружу с управляющим сервисом. Если школа полностью отключена от интернета, приватный LAN HTTPS ASA Lab продолжит работать, но удалённый tailnet-доступ из внешней сети может пропасть. При CGNAT использование Tailscale для администрирования возможно без белого IP, **но это не автоматическая публикация сайта для всех пользователей интернета**. Для публичного сайта понадобится отдельный HTTPS ingress на VPS с безопасным туннелем, DNS и защитой.

SSH и 1Panel имеют доступ к критическим ресурсам; используйте отдельные SSH-ключи, MFA и политику Tailscale ACL. Веб-доступ к 1Panel через HTTP внутри LAN/tailnet не становится дополнительным HTTPS сам по себе: для защиты браузерной сессии предпочтительны SSH port-forward и локальный браузер либо штатный TLS на панели. Не отключать 2FA ради API.

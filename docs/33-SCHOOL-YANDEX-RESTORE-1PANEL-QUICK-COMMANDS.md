## Быстрые команды (созданы и видны в 1Panel)

| Номер | Назначение | Команда |
|---|---|---|
| 00 | Срочный полный backup PostgreSQL+MinIO, запуск 24/7 | sudo asa-school-backup-now |
| 01 | Проверка облака без простоя | sudo asa-school-backup-now --check |
| 02 | Список зашифрованных архивов Яндекса, новых и старых | sudo asa-school-restore list |
| 03 | Скачать выбранную копию из Яндекса, не трогая боевую БД | sudo asa-school-restore download |
| 04 | Расшифровать выбранную копию офлайн-ключом и проверить ASA manifest | sudo asa-school-restore prepare |
| 05 | Пробное восстановление в отдельную новую PostgreSQL *_test | sudo asa-school-restore restore-test |
| 06 | Статус OAuth, ночного таймера и последней успешной копии | sudo asa-school-backup-now --status |
| 07 | Следующий запуск ночного бэкапа в 03:20 МСК | systemctl list-timers --all asa-school-nightly-database-backup.timer |
| 08 | Журнал ночных резервных копий | sudo journalctl -u asa-school-nightly-database-backup.service -n 80 --no-pager |
| 09 | Повторить OAuth вход, только если токен Яндекса отозван | sudo asa-school-connect yandex-reauthorize |
| 10 | Памятка для оператора | sudo asa-school-backup-now --help |

Статусы одобрения: все 11 команд созданы через штатный API и проверены. Реальный отбор и запуск команды пользователем через веб-интерфейс 1Panel ещё не проверялся.

## Сценарий восстановления

1. Выберите 02, найдите нужную дату/источник. Источник legacy означает старые копии из ASA-Backups; school означает новые из папки школьного приложения.
2. Выберите 03 и номер архива для скачивания. Команда не останавливает приложения, не меняет PostgreSQL/MinIO.
3. Выберите 04, снова выберите архив. Для age identity доступны два варианта: временно смонтированный root0600 файл на хосте Ubuntu под /media/, /run/media/ или /mnt/recovery/; либо нажмите Enter вместо пути и введите личный AGE-SECRET-KEY в скрытом запросе терминала 1Panel. При втором способе секрет находится только в анонимном Linux memfd (оперативная память), не в файле/аргументах команд. Его передачу через браузер и буфер обмена владелец должен оценить отдельно. **Не отправляйте ключ в чат, GitHub или Яндекс**. При ошибке расшифрования частично созданная staging-директория удаляется. После успешного расшифрования выполняется полная проверка ASA manifest и файловых хешей.
4. Для доказательства работы PostgreSQL выберите 05. Подтвердите RESTORE-TEST: создаст НОВУЮ тестовую базу PostgreSQL, не удаляя и не заменяя боевую. MinIO остаётся в staging; это НЕ боевой cutover.
5. Для полноценного развёртывания полученного архива на пустой сервер / замены действующей боевой системы необходимо отдельное управляемое задание: создать свежую копию текущей системы, проверить import-preflight и import-target-plan, развернуть новый изолированный Compose проект, импортировать PostgreSQL + MinIO + оригинальные ключи Student Code/шифрования, провести пользовательские тесты и только после явно принятого отката переключить трафик. У текущего штатного ASA manager НЕТ готовой операции безопасной полной замены живого инстанса. Поэтому опасную кнопку «перезаписать боевую БД» я не создавал.

## Безопасность

- Ни одна операция чтения/скачивания не удаляет данные в Яндекс Диске; staging хранится в /var/backups/asa-school-recovery с правами root 0700/0600.
- Офлайн приватный age identity на VM100 не хранится; нужен только для восстановительной операции.
- В проверке 01.11.2026 прямой TCP с D2-R2 в Tailnet блокировало защитное правило Windows codex_sandbox_offline_block_outbound, WSAEACCES 10013. Защиту не отключать и не обходить. Для текущей VM100 принят прямой MCP; также существуют терминал 1Panel и проверенный Proxmox/QEMU Agent.

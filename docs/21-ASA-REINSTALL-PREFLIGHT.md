SSH/1Panel, включая данные с Яндекс Диска. Выполнена только диагностика;
разрушительные команды, остановка сервисов и восстановление не запускались.

## Границы будущего исполнения

1. Уточнить политику замены текущих данных архивом и смысл «только в1Panel».
   Вопросы владельцу отправлены; ответы не подменяются истечением времени.
2. Выбрать проверенный выпуск и подтвердить полную доступность его образов,
   исходников, конфигурации и рабочего пути восстановления ДО удаления.
   PR680 адресов ещё не в main: переустановка сама по себе его не добавит.
3. Сохранить свежий согласованный полный backup PostgreSQL/MinIO/ключей/
   конфигурации с проверкой восстановления. В этом preflight backup НЕ создан.
4. Подготовить и независимо проверить конкретный сценарий переустановки и
   отката через поддерживаемые операции панели и канонические инструменты ASA.
   restore_apply в MCP всё ещё отсутствует; незавершённый PR583 не считается
   готовой процедурой. Прежняя rehearsal-квитанция не разрешает слепой cutover.
5. Область замены — только ASA asa-lab-dev. Сохранить 1Panel, OpenResty,
   asa-1panel-mcp, доступы/TLS/сайты, SSH и сеть. Не использовать глобальный
   prune, reset Docker или down -v. Любое удаление ограничить заранее
   идентифицированными объектами и подтверждённой политикой данных.
6. После восстановления проверить миграции, ACL, PostgreSQL вместе с MinIO,
   преподавателя/ученика, Scratch, сохранение и повторное открытие проекта;
   только затем объявлять переустановку принятой.

Воспроизведение read-only части: через подтверждённый SSH прочитать метки
working_dir/config_files контейнеров выбранного проекта, readiness, выполнить
агрегатные SELECT count(*) без идентификаторов и вызвать Compose search API,
не выводя его поле env. На D2-R2 вычислить Get-FileHash выбранного .tar.age;
на Ubuntu проверить комплект через deployment.contracts.verify_backup.
Ключ API остаётся в памяти авторизованного процесса; env/дампы/age identity
в этот репозиторий не попадают. Снимок: asa-reinstall-preflight.json.

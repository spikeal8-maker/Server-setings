## Обновление и восстановление

1. `asa_manager check` сначала блокировался `EDITOR_ENTRY`: `ASA_UPDATE_ENTRY_ORIGIN` оставался `http://127.0.0.1:4610`, тогда как родитель/runtime Scratch настроены на школьный HTTPS.
2. Изменён только `ASA_UPDATE_ENTRY_ORIGIN=https://x.asa-lab.ru` в приватном `.env`, исходная копия сохранена root-only. Перезапуска контейнеров для этого изменения не было. Повторная штатная проверка завершилась кодом 0, кандидат 287 доступен, CI проверен.
3. Свежий PostgreSQL dump восстановлен в отдельный `*_test`. Обычный `pg_restore` остановился на `ai_assistant_config_model_catalog_check`: функция `ai_model_provider_matches` читает `ai_ollama_cloud_models`, данные которого ещё не загружены. Такой же обычный restore primitive используется текущим и выбранным опубликованным менеджером. Полный штатный backup/restore пока не принят.
4. Для диагностической репетиции TOC изменён **только на копии**: данные `ai_ollama_cloud_models` восстановлены перед остальными TABLE DATA. Constraints, RLS и ACL не отключались. Это ручной обход для доказательства причины, а не установленное исправление штатного восстановления.
5. После восстановления отдельной копии выполнены `--plan`, реальная миграция 286 → 287 и smoke с повторной идемпотентной проверкой. Хеши строк до/после миграции совпали для accounts (96), projects/project_drafts (1742) и classroom_student_seats (513) на этой копии.
6. Финальный мигратор запущен явно с `--entrypoint node`; MIGRATION_DATABASE_URL, TEST_DATABASE_URL и APP_DATABASE_URL указывали на изолированную копию. Боевая база не подменялась, production migration не выполнялась.

Одна ранняя служебная попытка ошибочно запустила стандартный API-entrypoint вместо мигратора. У неё оставался исходный APP_DATABASE_URL. Только этот временный контейнер был остановлен; штатные контейнеры не перезапускались. Поэтому не утверждается, что за всю диагностику не было дополнительного служебного подключения к рабочей БД. Финальный успешный миграционный прогон исправляет обе границы — entrypoint и URL.

Финальная готовность рабочей школы подтверждена на исходном SHA/схеме 286. Временных репетиционных контейнеров не осталось. Все 50 нагрузочных сессий принудительно истекли. Копии БД и QA-проекты оставлены как свидетельства; тома, пользовательские работы и архивы не очищались.

## Воспроизводимая команда для приёмки при выпуске

В репозиторий добавлен `scripts/asa-release-load.py`. Он не устанавливает релиз и не создаёт credentials. Для выполнения нужны отдельные авторизованные синтетические StudentSeat и текущие сессии; файл fixture хранится **на узле развёртывания вне Git**, mode 0600. Он содержит `origin`, `authorizedSyntheticFixture: true`, 50 уникальных `seats: [{seat, token}]` и опциональные собственные QA documents для 3D/электроники. Нельзя подставлять реальные ученические сессии.

План не читает fixture и не делает сетевых запросов:

```bash
python3 scripts/asa-release-load.py \
  --origin https://x.asa-lab.ru \
  --revision FULL_TESTED_RELEASE_SHA
```

На явно выбранном тестовом развёртывании этой версии:

```bash
sudo python3 scripts/asa-release-load.py \
  --origin https://x.asa-lab.ru \
  --revision FULL_TESTED_RELEASE_SHA \
  --fixture /PRIVATE/authorized-synthetic-fixture.json \
  --output /PRIVATE/new-release-load-receipt.json \
  --apply
```

`FULL_TESTED_RELEASE_SHA` заменяется полным SHA фактически запущенного кандидата. Скрипт проверяет его до и после нагрузки и сверяет фактические 50 seatId через `/api/class-join/me`. Он создаёт до 150 тестовых проектов: каждый ученик проходит все три модуля. Для Scratch проверяется полный порядок upload → commit draft → read assets → reopen. Для остальных проверяется сохранение непустого собственного fixture, если он предоставлен. Снимки проверяются побайтово, доступ соседнего ученика должен быть отклонён. Default burst не содержит искусственных пауз и не делает автоматических повторов.

`--pace-ms 5000 --deadline-seconds 600` — отдельный диагностический сценарий поведения с паузами. Его нельзя подменять за burst acceptance. Default p95 каждого этапа должен быть ≤5000 мс; любой неожиданный HTTP/error, невыполненный journey, несовпадение SHA или deadline означает отрицательную квитанцию и ненулевой exit code. Redirect запрещён, чтобы не отправить Cookie/Bearer другому адресу. Общий процесс ограничен deadline, даже если HTTP peer постоянно присылает медленные байты. Сессии после приёмки должны быть отозваны/просрочены владельцем synthetic fixture.

**Hook в publisher или `asa_manager update` не установлен.** Само наличие этой команды не делает её автоматически обязательной при публикации. Это готовый проверенный HTTP-инструмент для включения в процедуру приёмки; полная обязательная приёмка дополнительно требует browser/AI/update/restore evidence одного кандидата. Текущий релиз остаётся заблокированным указанными выше результатами, а не объявляется зелёным по отдельному paced-прогону.

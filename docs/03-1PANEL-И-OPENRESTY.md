# 3. 1Panel v2.3.2 и работающий OpenResty

Управление сайтами, сертификатами, перезапуском OpenResty и журналами выполняется через 1Panel. Прямые правки `/opt/1panel/www/conf.d/*` подменяют генерируемую конфигурацию и могут быть потеряны при обновлении панели.

**Эталон тестовой Ubuntu:** 1Panel OSS v2.3.2, приложение `1Panel-openresty-fc55`, образ `1panel/openresty:1.27.1.2-5-1-focal`, локальный digest `sha256:ee8c5117c291c7384a381c32068e1d9a50adc8bf392f9157c42d14bedbbe018b`. Статус и образ сверять командами `docker ps`, `docker image ls --digests` (локальный digest не гарантирует наличие образа с ним в удалённом registry).

## Установка через официальную 1Panel

1. После первого входа откройте `Настройки → API Key → Создать API-ключ`; ограничьте IP. Временное действие ключа подписи — 5 минут; QR-привязку отключить.
2. На Ubuntu запустите `sudo python3 scripts/store-panel-key.py`: ввод скрыт, ключ сохраняется с правами 0600.
3. Выполните:

```bash
sudo python3 scripts/panelctl.py inspect
sudo python3 scripts/panelctl.py install-openresty
sudo python3 scripts/panelctl.py install-openresty --apply
```

Скрипт сверяет наличие закреплённой версии в **официальном App Store именно этого установленного 1Panel**, находит `appDetailId` и передаёт запрос `/apps/install` с HTTP 80 и HTTPS 443. Если магазин не содержит точной версии, скрипт остановится вместо автоматического выбора неподтверждённой. Если на 80/443 уже есть сервер, установка не повторяется.

## Известный сбой тестового сервера

Синхронизация каталога приложений не проходила, поэтому приложение OpenResty добавляли в **локальный магазин 1Panel**. Первый пакет имел неправильный формат файлов и не устанавливался. После исправления формата OpenResty был зарегистрирован в 1Panel и запущен; временный порт 18080 был заменён стандартными 80/443. Причина возникновения сбоя повторно не моделировалась на чистом VPS, поэтому полностью автономная установка через локальный магазин **не считается доказанной**. Не подменяйте приложение вручную независимым `docker run`: панель потеряет контроль над сайтами.

### Что делать, если магазин опять недоступен

* Проверьте DNS и TCP/HTTPS доступность адресов магазина **на Ubuntu**, не перенастраивая DNS/маршруты удалённого компьютера.
* Сохраните оригинальные журналы и версии 1Panel/App Store. Попробуйте официальный магазин/зеркало с проверкой происхождения; если нет — используйте инструкцию по **официальным local apps** 1Panel, без ручной записи в SQLite.
* Не копируйте вслепую базу `core.db` и `agent.db` с другой машины; состояние содержит привязки, пароли и специфические идентификаторы.
* Сохраните проверенный образ OpenResty (`docker save` + SHA256) во внешнем защищённом хранилище, если необходима офлайн-переустановка. Сам tar-образ в GitHub-код не кладём.

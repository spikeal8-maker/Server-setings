## Открытые вопросы

- **Полная UI-приёмка — NOT_ACCEPTED.** Несмотря на функциональный результат, UI v3 завершился `exit2 / BROWSER_FAILURES`: два SecurityError и два прерванных GET. Отдельная диагностика воспроизвела ошибку тестового инструмента Playwright. Последующий ограниченный probe реального Scratch с узким guard прошёл без page errors и service workers; документ и revision `3 → 3` сохранены, вход/выход и cleanup подтверждены. Остался один raw `auth-providers` GET `ERR_ABORTED`. Полный сценарий ещё не принят; приложение не исправлялось и ошибки не списаны.
- **Нагрузка — NOT_RUN.** Недоступны рабочая среда с локальным исполнителем и три файла контроллера запуска — factory/critical/poll. Нужно восстановить доступ и сверить их pins по [приложению](../snapshots/2026-11-08/school-current-readiness-evidence-20261108T074925Z.json). Проверенные D2 driver и VM observer/wrapper уже размещены; повторное размещение не требуется, новой staging-операции, run ID и нагрузки нет. Критический код не восстанавливать по памяти, проверки не обходить. **100 HTTP seats с save/read не означают 100 браузерных редакторов или полную ёмкость сервера.**
- **Административный API журналов — NOT_RUN.** Подготовлен отдельный QA-план входа, ограниченного grant/revoke и cleanup. Свежесть collector sources не заменяет эту проверку. `coverageComplete=false` и исторический lifecycle gap сохраняются.
- **Архив конфигурации и журналов — NOT_RUN.** Прочитаны только метаданные: host — **536 gzip-сегментов / 15759612 байт**, application — **5678 сегментов / 15187275 байт**. Наличие планируемой папки `app:/School-VM100/Configuration-Backups` пока **NOT_CHECKED**. Следующий пакет охватывает согласованные online SQLite-копии 1Panel, `1pctl`, зависимости FRP, статические настройки/ключи MCP и два нормализованных ZIP журналов. Живую bbolt БД не считать переносимой конфигурацией; после восстановления потребуется новая OAuth-регистрация. Подробные незакрытые проверки файлов — в приложении. Полная история логов не входит в portable PostgreSQL/MinIO backup.

Испытания не совмещать с активным backup: он временно останавливает writers. Два фактических one-shot restart нового backup приняты отдельно, исходный внешний `exit2` сохранён при native `exit0`.

3. Пройти [готовый регламент перехода и возврата](30-SCHOOL-DOMAIN-MIGRATION-RUNBOOK.md): финальный запрет записи на H04, свежий экспорт БД/объектов, проверка восстановления, решение о повторном входе и приёмка HTTPS-маршрута. **Переключение домена — только по последующей отдельной инструкции о cutover.** SMTP/боты остаются выключенными на тестовой копии; ИИ/VPN — позже.

После школьных записей потребуется их обратный перенос или reconciliation; просто вернуть DNS к прежней H04-БД нельзя. **Полный live rollback NOT_RUN.**

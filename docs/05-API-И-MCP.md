## Создание ключа

1. Локально откройте `http://192.168.1.115:19192` с полным защищённым путём входа, либо сделайте SSH-туннель. Веб-интерфейс доступен только через LAN/Tailscale, **не через публичный WAN**.
2. `Настройки → API Key → Создать API-ключ`: имя `asa-lab-private-mcp`, белый список `127.0.0.1`, `192.168.1.111`, `100.96.255.113` на текущем тестовом сервере; на **другой машине** использовать реальные разрешённые IP и только нужные источники.
3. Срок подписи запроса — 5 минут (значение `0` запрещено — оно отключает контроль времени); срок ключа — ограниченный, QR-привязка отключена; запрет «Любой IP».
4. На сервере `sudo python3 scripts/store-panel-key.py`, введите ключ **скрытым вводом**. Не помещайте его в команду shell/аргументы процесса/CI/репозиторий. Для диагностики: `sudo python3 scripts/panelctl.py inspect`.
5. Владелец может отозвать ключ через интерфейс панели; после отзыва сервис MCP надо отключить или настроить с новым ключом. Права ключа в 1Panel **административные**, а не только чтение.

## Как работает подпись API v2

Для каждого запроса 1Panel API используются заголовки:

`1Panel-Timestamp = текущее время Unix в секундах`, `1Panel-Token = hex(MD5("1panel" + API_KEY + Timestamp))`. `scripts/panelctl.py` реализует схему и не выводит сам ключ. Это протокольная подпись 1Panel, **не** криптографическое ограничение полномочий. HTTP к 19192 допустим лишь в изолированном контуре; для доступа за пределами приватной сети нужен TLS/SSH tunnel.

## Локальный официальный `mcp-1panel`

Используется исходный код `https://github.com/1Panel-dev/mcp-1panel`, закреплённый commit `6cd495d74010e762e0ab6ce3ead31730f8ba572a`. Официальный MCP по умолчанию имеет `readonly` и лишь шесть инструментов чтения. В режиме `readwrite` добавляет создание сайтов, сертификатов и БД. `full` позволяет установку приложений и потому **не предлагается** для типового ИИ-оператора.

Запуск (только после получения ключа и установки 1Panel):

```bash
sudo bash scripts/setup-mcp.sh
sudo bash scripts/setup-mcp.sh --apply
sudo systemctl status server-settings-1panel-mcp --no-pager
```

Скрипт собирает бинарник из закреплённого коммита (требуется доступ к Go-модулям), создаёт `EnvironmentFile` с правами 0600, стартует systemd службу на **`http://127.0.0.1:39443/mcp`**, только loopback, и проверяет `401` без Bearer. MCP Bearer-токен хранится в `/etc/server-settings/mcp.env`. Не открывать 39443 в UFW, NAT и 1Panel. Удалённая прямая интеграция с облачным ChatGPT **не возникает автоматически**: ему нужен авторизованный транспорт (например, через управляемый локальный компьютер) либо отдельный HTTPS/OAuth-gateway, который здесь **не установлен**. Локальный HTTP Bearer не предназначен для публикации в интернет.

При использовании MCP через SSH-туннель проверьте, что сервер доступен только уполномоченному клиенту, а ключ находится только в защищённом окружении. Для чтения `readonly` не даёт инструментов создания/изменения. Для расширения действий требуется отдельная проверенная роль и согласованная процедура.

Официальный API позволяет больше, чем текущий MCP: например, изменение параметров существующего сайта. Для таких операций использовать 1Panel UI или отдельно утверждённый API-клиент; нельзя считать, что MCP обладает всеми возможностями веб-интерфейса.

**Дополнительная защита:** `scripts/panelctl.py` позволяет читать панель через LAN/Tailscale, но команды `--apply` с изменениями сайта/OpenResty принимаются только при запуске **на самой Ubuntu** к `http://127.0.0.1:19192`. С компьютера D2-R2 изменения выполняйте через авторизованный SSH на Ubuntu, а не слепым удалённым API-запросом.

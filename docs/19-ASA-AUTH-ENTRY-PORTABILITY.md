## Что установлено

- Проверка «Я не робот» подписывает действие, nonce, время и User-Agent,
  но не IP. Срок10 минут; перезапуск API инвалидирует незавершённую проверку.
  Повторное использование отклоняется. IP участвует отдельно в ограничении
  частоты запросов; общая школьная сеть может делить этот бюджет, но такой
  отказ на школьном сервере пока не доказан.
- Вход с неподтверждённого origin получает403 origin_forbidden. Это отдельный
  механизм от пароля. GET readiness не доказывает работоспособность POST login.
- Личная форма маскировала403 общей ошибкой сервера, организационная — ошибкой
  реквизитов. Это подтверждённый дефект диагностики, а не доказательство
  причины каждого пользовательского отказа.
- Cookies привязаны к хосту: домен и IP имеют разные сессии.
- На HTTPS-домене и LAN-входе runtime-config и встроенный Scratch возвращают
  фиксированный https://test.asa-lab.ru. В main браузерная часть уже использует
  текущий origin, но серверная выдача Scratch-сессий всё ещё зависит от
  ASA_BLOCKS_RUNTIME_ORIGIN. Одного обновления браузерного кода недостаточно.

## Постоянное решение, ещё не реализованное этим PR

Использовать существующие Portable Deployment Standard и
ADR-PORTABLE-DEPLOYMENT-TRANSITION-001; текущий статус переходный,
TRANSITIONAL_NON_COMPLIANT, открыты EX01/EX02.

1. Образ не содержит адрес конкретного компьютера. Установка хранит один
   основной HTTPS-адрес и явно разрешённые дополнительные адреса отдельно от
   пользовательского дампа; обновление сохраняет настройки и ключи установки.
2. Web, API и встроенный Scratch работают через один вход и относительные пути.
   Сервер выдаёт Scratch-сессию для проверенного адреса входа, сохраняя проверки
   пользователя, проекта, версии, режима, срока и postMessage origin/source.
3. Настройка адреса установки и диагностика могут быть представлены в админке;
   это интерфейс к общей конфигурации, а не отключение проверок безопасности.
4. Убрать адреса прежнего сервера из шаблонов Compose/Caddy и проверить чистую
   установку, восстановление пользовательских данных, обновление и перезапуск.
5. Приёмка: вход преподавателя/ученика с разных компьютеров, Scratch, сохранение
   и повторное открытие; неверный origin и чужой postMessage по-прежнему отвергаются.

Нельзя заменять это CORS wildcard, доверием к любому Host или отключением
bot-check. Простое сохранение HMAC-секрета при потере in-memory replay-журнала
тоже не является корректным исправлением. DNS/TLS на новом сервере остаются
настройкой конкретной установки, а не частью пользовательской БД.

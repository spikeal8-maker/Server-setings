# Отключение MPTCP как меры защиты

2 ноября 2026 года на домашнем тестовом сервере `admins-MS-7D22` установлено `net.mptcp.enabled=0`. Основание — [официальный релиз 1Panel v2.4.2](https://github.com/1Panel-dev/1Panel/releases/tag/v2.4.2), где отключение MPTCP указано как мера против CVE-2026-98432. Это компенсирующая настройка, а не утверждение о доказанной эксплуатации или полной защищённости ядра.

После загрузки нового ядра `7.0.0-42-generic` значение было `1`. Проверенный скрипт `scripts/disable-mptcp.py` изменяет только этот параметр и создаёт `/etc/sysctl.d/90-asa-no-mptcp.conf` для последующих загрузок. Он не выполняет `sysctl --system`, не перезапускает сеть, SSH, Docker или Tailscale и не меняет порты.

```bash
# План без изменений
sudo python3 scripts/disable-mptcp.py
# Применить на проверенной машине
sudo python3 scripts/disable-mptcp.py --apply --expected-host ACTUAL_HOSTNAME
```

Перед применением проверены существующие активные настройки MPTCP в sysctl.d: конфликтующих значений не найдено. Чужой конфигурационный файл скрипт не перезаписывает. Исходное значение и факт прежнего существования файла записаны root-only в `/var/backups/asa-mptcp-mitigation/before.json`. Для отката нужны отдельный разбор причины, восстановление записанного значения и удаление только принадлежащего этому скрипту файла, если до применения его не было. Не возвращать уязвимый режим без необходимости.

Независимое ревью точного source `e2facca` — PASS. После применения новый SSH по ключу и sudo UID0 работают. Реальная команда полного MCP `2e37975464384cbb8e122e1fb681fa59` завершилась success: UID0, MPTCP0, SSH/1Panel/MCP/Docker active. Поддержка обычного TCP сохранена. Повторная загрузка после именно этой настройки не выполнялась, поэтому persistence пока подтверждается файлом, а не вторым boot-тестом.

Общая программа безопасности остаётся незавершённой: отдельно выполняются исправления зависимостей, CSP, образов и резервного копирования. Эта настройка не заменяет эти работы.

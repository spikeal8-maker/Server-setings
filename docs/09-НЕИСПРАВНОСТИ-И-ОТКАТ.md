# 9. Диагностика распространённых проблем

**Нет сайта в 1Panel, но HTTPS работает.** Возможно, запущен независимый Caddy/Nginx вне 1Panel. Сравнить владельцев портов: `sudo ss -lntp | grep -E ':(80|443)\\b'`, записи панели и site конфигурацию. Никогда не выключать действующий веб-сервер до проверки нового.

**OpenResty не появляется в магазине.** Проверить официальный источник приложений и синхронизацию. В текущем историческом случае использовался local app store; первая копия содержала неверный формат, затем исправлена. Локальные YAML/метаданные должны соответствовать контракту версии 1Panel; исправление на новой машине не подтверждено.

**Порт 18080 отвечает, 80/443 нет.** Это промежуточная миграционная схема. На действующей Ubuntu 19.10 OpenResty на 80/443, временный 18080 не используется. Не запускайте два веб-сервера на одном IP:port.

**После reboot пропал публичный HTTPS.** Сначала `sudo systemctl status asa-lab-public-ip.service`, `docker ps`, `ss -lntp`. Старый публичный Caddy пока `enabled` и может конкурировать с OpenResty. После проверки и backup применить `sudo python3 scripts/serverctl.py repair-public-caddy --apply`: отключится только старый автозапуск. Не удалять rollback-конфиг без отдельного решения.

**API 1Panel отвечает 401/403.** Проверить статус ключа в панели, дату/время сервера, allowlist реального source IP, `1Panel-Timestamp`, подпись, поддержку API на версии 2.3.2. Проверка по HTTP без авторизации не доказывает работоспособность API. Не разрешать `0.0.0.0/0` ради теста.

**Ошибка `origin_forbidden` при входе в ASA Lab.** Учитывать HTTPS origin со схемой+IP+портом и конфигурацию `.env`. Не удалять CSRF/anti-origin. Локальная CA Caddy должна быть явно доверена на новых клиентах; это отдельная задача.

**Публичный IP изменился, порт недоступен.** Проверить белый IPv4 против CGNAT, правила NAT и UFW, новый IP в сертификате/сайте/ASA Lab origins. Панель должна оставаться доступной через Tailscale или LAN. Новый IP требует нового сертификата, старый не переносится.

**Не пришёл новый сертификат Let's Encrypt.** Проверить ACME-аккаунт 1Panel, журналы и доступ HTTP challenge на 80, TLS сайт, открытие порта роутера и ограничения CA. На IP краткий срок действия, поэтому отказ обновления быстро ломает доступ.

**Новый Docker поднял пустую базу.** Сразу остановить операции записи, зафиксировать тома/Compose project, не удалять данные. Использовать bootstrap/restore только после сверки зашифрованного архива и наличия текущей копии.

**Откат.** Каждый шаг документируется в GitHub PR; перед применением снять конфигурацию и данные независимыми процессами, иметь доступ по SSH/консоли. Откат новой 1Panel/OpenResty выполняется снимком/штатным инструментом; заменять исходную БД панели необработанной файловой копией опасно. Git revert возвращает только исходники установщика, **не** автоматически состояние сервера.

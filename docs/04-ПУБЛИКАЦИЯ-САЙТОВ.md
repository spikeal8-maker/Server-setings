# 4. Публикация сайтов: публичный IP, домен, LAN и динамический IP

## Эталон текущего ASA Lab

Интернет → роутер (WAN 94.29.44.211, NAT только 80/443) → Ubuntu 192.168.1.115 → OpenResty 1Panel → `http://127.0.0.1:4610` → Docker Web. Локальная сеть → `https://192.168.1.115:4610` → Caddy с локальным CA → тот же Docker Web. PostgreSQL/MinIO/внутренний API наружу не выставляются.

Проверенные настройки обратного прокси: `templates/asa-lab.public-proxy.conf`, эталон vhost `templates/asa-lab-public-ip.conf.reference`. **Оба файла предназначены для чтения и сравнения**, а не для слепого копирования поверх записей панели.

Создание HTTP proxy-сайта на **новом** сервере, где уже доступен backend:

```bash
sudo python3 scripts/panelctl.py create-site --site-host 94.29.44.211 --site-upstream http://127.0.0.1:4610 --site-alias asa-lab-public-ip
sudo python3 scripts/panelctl.py create-site --site-host 94.29.44.211 --site-upstream http://127.0.0.1:4610 --site-alias asa-lab-public-ip --apply
```

На любом другом сервере значения `--site-host` и `--site-upstream` обязательно соответствуют его собственному адресу и **реально работающему** приложению. Скрипт не изменяет уже существующие сайты и не включает HTTPS фиктивно. Для HTTPS: **1Panel → Сайты → нужный сайт → HTTPS**; привяжите ACME-сертификат или импортируйте валидный, включите HTTP→HTTPS, TLS 1.2/1.3, автоматическое продление, проверьте `curl -Iv` с клиентской машины.

## Публичный IP без домена

У текущей Ubuntu настоящий Let's Encrypt-сертификат **для IP 94.29.44.211**, а не самоподписанный. Период 19–26 октября 2026 (UTC); короткоживущие сертификаты для IP требуют частого автоматического обновления. 1Panel API показывает `autoRenew=true`, но нужно реально проверить повторный выпуск и повторную загрузку в OpenResty, пока ещё есть время до окончания срока. Сертификат привязан к IP и не перенесётся автоматически на другой IP/VPS.

## Несколько проектов на одном IP

С доменами: `project-one.example` и `project-two.example` различаются по `Host`/SNI на общем 443 в 1Panel. Без домена можно выдавать разные внешние **HTTPS-порты** (например, 443 и 4620), но это требует отдельного `listen`, сертификата на IP и разрешения/NAT порта; само наличие контейнера на 4620 не создаёт публичный маршрут. Для будущего рекомендуются собственные DNS-имена и стандартный 443.

## Динамический IP / CGNAT

Доступ **к панели**: Tailscale и порт 19192 только по tailnet/LAN; router port forward 19192 никогда не делать. При смене WAN IP Tailscale обычно сохраняет связь, если доступен исходящий интернет. Для **публичных сайтов**: домен+DDNS при доступном белом IPv4 или отдельно проверенный туннель/внешний reverse proxy; при CGNAT обычный входящий NAT не сработает. Cloudflare Tunnel для данной сети ранее не подходил, возможен FRP через VPS при отдельно согласованных портах и TLS. Скрипт **не устанавливает FRP автоматически** и не обещает публичный HTTPS из-за CGNAT без дополнительного ingress.

## Локальный HTTPS без интернета

Caddy на LAN использует `tls internal` и собственный CA. Это независимая от публичной сертификатная цепочка; при входе со школьного компьютера возможна ошибка доверия, пока CA доверенно не установлен. **Не отключать CSRF/origin-проверку, чтобы обойти ошибку входа `403 origin_forbidden`.** Учитывайте, что в ASA Lab в `.env` перечислены точные разрешённые origins. Локальные IP в будущем могут измениться; нельзя жёстко пришивать 192.168.1.115 ко всем установкам.

# 10. Техническое задание новому боту с нулевым контекстом

Ты отвечаешь за инфраструктуру `spikeal8-maker/Server-setings`, а не за разработку портала ASA Lab. Сначала прочитай `AGENTS.md`, весь `docs/` и структурированный `snapshots/2026-10-19/test-ubuntu.json`.

Протокол работы:

1. Проверить GitHub HEAD, сетевые узлы и сохранённые эталоны. Пользовательский тестовый сервер — `admins-MS-7D22` (Ubuntu) в LAN 192.168.1.115, а не Windows школа / VPS leticia.
2. Получить свежий read-only аудит: панели, версии Docker, OpenResty, UFW, SSH, Tailscale, сертификатов, сайта, базы и состава резервных копий. Никаких секретов в чат/PR.
3. Открыть отдельную ветку, составить план, подготовить rollback. Один исполнитель пишет конфигурации, независимый ревьюер проверяет безопасность и повторяемость.
4. Все установщики запускаются сначала без `--apply`. На работающей машине новые установки запрещены; необходим отдельный чистый Ubuntu тестовый сервер, где можно проверить полный цикл и повторный запуск.
5. Отработать сценарии `home-static`, `home-dynamic`, `vps`; подготовить подтверждённый способ получения OpenResty и продления IP TLS, проверить реальный `mcp-1panel` по `tools/list`, а не по открытому TCP порту.
6. Провести unit tests + smoke + security review + реальный reboot/restore только на специально выделенном тестовом узле. Исправить все ошибки, не теряя данные ASA Lab.
7. По окончании опубликовать PR, точные коммиты, протокол PASS/FAIL/UNKNOWN и краткую русскоязычную инструкцию для владельца. Не объявлять готовность, пока независимая новая установка не завершена.

Критерий полезного результата для владельца: один читабельный набор файлов, из которого без поиска старых чатов ясно **что установлено, как это проверить, как переустановить, как добавить сайт и как восстановить управление**.

## Как применять после интеграции и публикации выпуска

Из канонического каталога ASA, код менеджера которого содержит эту функцию:

```sh
python tools/asa_manager.py configure-entry --root /srv/asa-lab --entry-profile asa-owned --entry-origin https://test.asa-lab.ru
python tools/asa_manager.py configure-entry --root /srv/asa-lab --entry-profile asa-owned --entry-origin https://test.asa-lab.ru --apply
```

Первый вызов — план без изменения файлов. Второй сохраняет публичные настройки
в существующей приватной `.env`, сохраняя секреты, свои дополнительные адреса,
владельца/права файла на POSIX и приватную копию отката в
`.asa/private-entry-backups/`. Эту копию нельзя публиковать. Повтор идемпотентен.
На школьной установке выбрать её проверенный основной HTTPS-вход и реальный
канонический каталог; не копировать каталог Ubuntu в Windows-команду.

Далее применяется штатное защищённое обновление ASA с backup. Если SHA выпуска
тот же, менеджер всё равно обнаруживает неприменённую конфигурацию и проводит
обычный backup/switch. Совпадающая конфигурация сохраняет NO_CHANGE. Обычные
обновления читают сохранённые настройки; профиль не требуется выбирать заново.
Профиль не навязывается всем сторонним установкам из GitHub автоматически.

Эти команды не меняют DNS, сайты 1Panel, сертификаты, firewall или контейнеры.
Для каждого используемого адреса ingress обязан сохранить исходный Host и
обеспечить HTTPS с доверием браузеров. Нужный DNS/сертификат для будущего
поддомена по-прежнему создаётся отдельно; список приложения расширять не надо.

## Что изменено в ASA

В opt-in режиме Scratch получает сессию для текущего разрешённого адреса.
Единая политика применяется к выдаче, runtime GET/PUT/OPTIONS и сохранению.
Подписанный токен остаётся привязан к одному точному origin, проекту,
пользователю, разрешениям и сроку. Отзыв доступа проверяется повторно.
Шаблон регистрации зоны не превращается в wildcard postMessage или JWT.
Проверяются границы DNS-суффикса, HTTPS/порт и совпадение фактического Host
для поддоменного входа; X-Forwarded-Host не даёт доверия.
Прежний фиксированный режим и redirect www на основной домен сохранены.
